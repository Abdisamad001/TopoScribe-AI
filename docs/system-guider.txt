📘 PROJECT IMPLEMENTATION GUIDE
Agentic AI System for Natural Language–Driven Network Design, Configuration, and Simulation
🎯 Project Goal (Put This at the Top in Cursor)

Build a web-based agentic AI system that allows users to describe a computer network using natural language.
The system automatically generates a network topology, device configurations, logically simulates connectivity, allows conversational modification, and produces a professional deployment-ready report.

🧩 PHASE 0 — Foundations & Constraints (DO NOT SKIP)
Objective

Establish clear boundaries to avoid over-engineering.

Requirements

This is a logical/control-plane simulation, not physical packet emulation

No real IOS, no real routing daemons

Focus on design correctness, reachability, and documentation

Expected Output

A short document (README.md) stating:

What the system does

What it intentionally does NOT do

✅ Checkpoint:
Supervisor agrees with scope.

🧩 PHASE 1 — Core Data Models (System Backbone)
Objective

Create the single source of truth for the entire system.

Requirements

Define schemas for:

NetworkNode (router, switch, host)

Link

Protocol

Topology

Cursor Prompt

“Create TypeScript interfaces (or Python Pydantic models) for network nodes, links, protocols, and topologies. Keep them generic and extensible.”

Expected Output

Node with id, type, interfaces, config

Link with source, target, bandwidth

Topology JSON representation

Example:

{
  "nodes": [],
  "links": [],
  "protocols": []
}

🧩 PHASE 3 — Backend Simulation Engine (Your Real Contribution)
Objective

Implement logical network simulation.

Requirements

Graph-based model

BFS / Dijkstra

Rule validation

What You Implement

Graph construction from topology

Routing rules:

static routing

OSPF (shortest path)

VLAN isolation rules

Cursor Prompt

“Create a backend service that converts a network topology into a graph and simulates reachability between nodes based on routing and VLAN rules.”

Expected Output

API endpoint:

/simulate/ping

Returns:

{
  "success": true,
  "path": ["PC1", "SW1", "R1", "R2", "Server"]
}


✅ Checkpoint:
Packet path animation works in UI.

🧩 PHASE 4 — Protocol Modeling Layer (NOT Implementation)
Objective

Support networking protocols logically.

Requirements

Define protocol rule tables:

OSPF

EIGRP

VLANs

Static routing

Cursor Prompt

“Create a protocol rule engine that validates protocol requirements (e.g., OSPF area match, router ID uniqueness) without implementing protocol internals.”

Expected Output

Validation errors when configs are wrong

Correct routing when configs are valid

✅ Checkpoint:
Changing protocol parameters changes simulation results.

Output:

Links
